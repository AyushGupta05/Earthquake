# Deployment adapter API

This is a source-only adapter. It never infers funding or scientific authority and has no autonomous cloud entrypoint. No numerical model source is edited. ROOT runs exactly one frozen parent-controller stage at a time after the independent prerequisite checks. All real paths, pins, receipts and data remain ROOT inputs.

## ROOT configuration

`Deployment(config, root_authority, systemd, clock=monotonic)` implements the frozen parent and child adapters. Exact top-level config keys:

- `schema`: `marked-deployment-config-v1`.
- `sources`: exact roles `processor`, `gaussian`, `native`, `parent`, `adapters`.
- `runtime`, `inputs`, `protocol`, `publication`, `bootstrap`, `commands`.
- `store_directory`, `storage_limit_bytes`.
- `authority_source`, `authority_config`.

A file spec is exactly `{path: absolute canonical path, pin: {bytes, sha256}, mode: integer POSIX mode}`. Source files are0400. Runtime critical modes are the exact original values, including0664/0775; no normalization. A source-role spec is `{directory, files: {relative_path: pin}, manifest: file_spec, upload_manifest: file_spec|null}`. Closed role counts are processor32/Gaussian34/native22/parent32. Adapter inventory is its complete published allowlist. No unlisted files or directories, symlinks, omitted code, or extra Python are allowed. The only excluded upload artifact has exact name `parent_upload_manifest.private.json`, is separately pinned0400, and its parsed map must equal `files`. The first-clean manifest must cover every role member except its own recursive hash and the existing published bookkeeping (`ALLOWED_PUBLIC_FILES.txt` for parent/adapters, `SHA256SUMS` for Gaussian). All processor reference copies must equal the positively bound Gaussian/native role code. Source imports execute those exact verified bytes, never ambient filenames.

`runtime` exact keys: `directory`, `manifest` (file spec with JSON `files` map of10112 `venv/...` pins), `symlinks` (file spec with JSON `symlinks` map of exactly4 relative paths to exact link targets), `critical` (10 absolute paths mapped to `{bytes,sha256,mode}`), `python` (absolute venv path resolving to a verified member), `versions` (exact python/numpy/scipy/torch strings), `regular_mode`=0444. Critical artifacts need not lie in the venv. Symlink destinations must resolve to positively verified files or directories derived from verified runtime members. Before vendor execution, running sys.executable must resolve to the pinned interpreter and isolated/-B flags must hold. Preloaded NumPy/SciPy/Torch are rejected. A persistent import guard checks vendor and transitive non-stdlib module origins, standard loader classes, verified hashes and package search directories against the closed runtime inventory, including later lazy optimizer imports. Python builtin/frozen/stdlib authority remains with the bound interpreter; site/dist-packages are not treated as stdlib. Positively bound source modules and ROOT authority are separate allowed source roles. No install or chmod occurs. Target tests must use the original runtime; metadata-mode truth is an external ROOT prerequisite.

`inputs` exact gate keys: feature_archive/feature_manifest/feature_authority/strong_results/strong_authority, each a positive file spec <=16MiB. Feature archive/manifest remain frozen native representationV1; fitting/admission/checkpoints remain distinct V2. `protocol`, `publication`, `bootstrap`, `authority_source`, `authority_config` are positive file specs. Bootstrap must be an exact member of the adapters role. `commands` exact systemctl/systemd_run positive executable specs; no shell expansion. Store is an existing private0700 directory with ROOT-approved total bytes cap. All input paths must be free of symlink ancestors. Parent ROOT driver imports these positively bound adapters and passes its independently loaded authority factory; the sole-stage bootstrap repeats source/runtime/input checks before scientific imports.

## Authority registration

The separately reviewed ROOT `authority_source` exposes:

```
make_validator(config, *, io, source_binding, clock, expected_deployment_config_pin) -> callback
callback(scope, documents, now) -> receipt
```

The factory receives the **full deployment config** and positively bound adapter modules. It reads the separately pinned `authority_config` file for evidence specifications. Parent ROOT CLI positively verifies the full deployment config bytes and supplies its canonical pin as `expected_deployment_config_pin`; the factory verifies canonical full config equals that independently supplied pin. The child uses the explicit expected pin retained in the positively pinned immutable launch frame, compares canonical config before the factory call, and supplies the same kwarg. Never derive expected authority from incoming scope or embed the full-config hash inside its own configuration. This is an acyclic chain: independent public validator source, private authority config, deployment config, then outer pinned launch frame. The callback must independently validate fresh funding/resource authorization, published full source/runtime/target tests, actual native build/replay agreement and all original strong numerical closures. Fixture booleans are not authority. Parent registration uses this same factory and dependency modules; there is no permissive default or alternative standalone verify shim. The adapter checks exact result schema/subject/evidence/lease but does not replace ROOT's proof semantics.

`scope` keys: gate_sha256, config_pin, index, unit, source_pins, runtime_pin, input_pins, funding_pin, publication_pin, phase (`parent` or `child`). `documents` exact keys publication/feature_authority/strong_authority/strong_results, raw bytes. Receipt exact keys: schema=`root-marked-stage-authority-v1`, scope equal supplied scope, decision=`authorized`, expires finite same-host monotonic, evidence_pins with publication/feature/strong/funding. Parent lease must cover full manager interval at dispatch; child must be within that original lease. Source gates and external authority are checked again in the child; their verification time is charged to the original source budget.

## Store and contained execution

`secure_io.Store` implements frozen `write/read/exists` with two-part `stage_XX/name.json` logical paths. Each snapshot <=2MiB; current total cap and4096-member cap are enforced under a nonblocking process/thread lock. Immutable files are atomically linked exclusively, latest_update.json alone can be replaced atomically; temporary bytes require full headroom. File data+metadata and directories sync, then bytes are read back. Partial temporaries remain as failed custody evidence and prevent progress. Store failures never manufacture a success. `.store.lock` is separate0600 bookkeeping.

`Systemd` uses positive command bytes, exact owned unit only, no retry. Bounded transport retains64KiB stdout/128KiB stderr plus hashes/counts; truncation or uncertain EOF marks incomplete. Default real transport uses subprocess pipes; invented tests use subprocess fakes or temporary local Python processes only. Zero-timeout cleanup submits only a nonblocking stop request, explicitly **not** verified cleanup. `live` checks observed cgroup memory/swap/tasks/CPUWeight/process membership plus systemd RuntimeMax/stop/KillMode/MainPID/ControlGroup and thread/CUDA environment. ROOT must independently verify unit emptiness after dispatch.

`Deployment.run` writes immutable bootstrap.json and uses frozen `controller.systemd_command`. Its inline launcher captures source monotonic origin before loading bootstrap bytes, verifies size/hash, and invokes one stage. Bootstrap receives launch file absolute path plus exact SHA256. No stage loop, resume, optimizer fallback or retry exists. Parent preparation consumes the already supplied transport deadline. Child scientific imports, loading, all87 positivity validation and source work consume original300/900 budgets; manager360/960 and whole7200+200 remain unchanged. Target verification must measure hash/preparation overhead; this source adds no cap increase.

## Old strong comparison projection

`comparison_join.project(packet, old_envelope, join_proof_pin, new_comparison_sha256)` requires ROOT independent proof before use, then checks all actual roster/forecast identities itself. `old_envelope` exact keys schema=`root-original-strong-comparison-input-v1`, original_packet_pins (`archive`,`manifest`), original_packet_sha256, roster, fits. Roster is87 ordered common entries `{ordinal, partition, mw, group, horizons:[1,3,5]}`; fits are seed-major B/F/H/T for20261012/13. Each fit retains complete528 original numeric forecasts and original checkpoint/result/source/closure pins. Independent closure contains verified/checkpoint_sha256/source_sha256/packet_sha256/no_optimizer/proof_pin. ROOT may attach extra fit provenance fields.

Historical storage identified the original packet by archive+manifest pins. If `original_packet_sha256` is newly derived SHA256(canonical original storage-pair pins), ROOT must explicitly attach `original_packet_sha256_semantics` to every fit; it is preserved and is never called a historical logical-packet hash. Adding seed/arm/status from already closed fit identity is permitted with ROOT proof; no numerical field is fabricated. B/F have no quantiles and retain that omission; H/T retain their seven existing quantiles.

The projection changes only the aggregate's packet_sha256 and closure packet_sha256 to the marked **comparison population** hash. Its origin object retains original packet pins/hash, result/checkpoint/source/closure pins, join proof and `old_model_reexecuted=False`; any extra fit provenance remains unchanged. If a fit already has an `origin` object, its exact content is retained as `origin.original_fit_origin`; original packet-hash semantics also remain as the original top-level field and are repeated in join origin metadata. This never claims the old models consumed marked features. Frozen processor validates all proper numeric score fields afterward. New S/P/D outcomes still require an independent audit before scientific conclusions.
