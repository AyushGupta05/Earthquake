# Minimal prospective controls and invented tests

Advisory only; no implementation or generated/decoded binary fixtures exist. The root freezes controls before source implementation or actual input use.

1. Parent verifies complete whole transport custody and exact immutable bounded bytes. Scanner independently rejects skips, full-SEED/padding, missing/duplicate 1000, non-ASCII identities, invalid exponent/word order, ambiguous header interpretation, trailing fragments, cross-record or excessive blockette links and unresolved extensions.
2. Scanner enumerates every actual record, validates a prospective uniform body length/header order, independently checks encoding and fixed-width input capacity, and sums each unsigned advertised count. Record, identity/descriptor, sample, total-study and output limits are checked before import or payload allocation. No first-record multiplication or coalesced-trace shortcut.
3. A parent-selected worker inherits a deliberately minimal environment. Clear byte-order/encoding overrides before importing the decoder; pin and pass the admitted header byte order and record length. Do not substitute a more convenient record interpretation or fallback encoding. Process exactly one body at a time and discard arrays before advancing.
4. Before actual use, independently demonstrate effective memory/address-space enforcement and bounded output/wall-time control on invented over-limit workers in the selected platform. Raw byte limits and the public planning formula are not proof of native allocation bounds. If effective containment or narrow format checks are unverified, do not invoke payload decode.
5. Reconcile decoded counts and identities against the immutable structural ledger. Reject partial success, C/Python decode errors, incompatible warnings or ledger mismatch. A source-level segment total cannot prove each record clock; raw timing remains unverified even when counts agree.
