# L runtime adapter: source-only cold module binding

`load(mode, config, *, expected_config_pin, io, sb, check, prefix)` is a context manager. `mode` is exactly `producer` or `independent`; `prefix` matches `eew_l_[a-z0-9_]{1,64}`. Each positively loaded adapter module is single-use, including after a failed attempt. ROOT must hold the context (usually through its outer ExitStack) across the ENTIRE scientific operation, returned result and final checks. Returning its dictionaries from `bind` and immediately exiting the context is invalid. No real data are read or decoded here; no files, resources, credentials or financial evidence are written or invented.

`io` and `sb` are ROOT's separately positively loaded unchanged V6 secure_io/source_binding modules, with vendor_inventory/generated_source/metadata_finder dependencies. This adapter verifies their file/profile and transitive module identities; ROOT establishes that the injected objects were executed from those positively bound bytes, rather than treating `__file__` or a Boolean as such proof. The adapter itself is loaded from its positively closed `adapter` profile. `check()` is ROOT's existing deadline/lease checker captured before all imports. It is called during source/runtime reads, group loading, inside the unchanged vendor guard and before normal or exceptional context exit. This adapter grants no source-clock reset, retry or larger cap.

## Loader config and execution config are distinct

The exact loader config keys are `sources`, `runtime`, `role_subjects`, `original_source_pins`. `expected_config_pin={bytes,sha256}` must be held independently by ROOT before the call, and binds canonical JSON of this complete loader config. It must not be computed from an untrusted requested config as evidence of authority.

`runtime` is the complete unchanged V6 runtime spec: full10112-member prefix,10critical files in original modes,4symlinks, positive supplemental RECORD inventory, exact generated helper and metadata finder, interpreter and versions. The actual V6 runtime verifier runs before vendor imports; the V6 guard remains active through lazy imports and caller work. No version string or ambient sys.path entry grants execution permission. The full V6 guard is reused, including cold bound-root discovery, verified-source compilation, optional absent-module semantics and exact metadata-only finder. Torch's approved generated helper remains the only permitted unlisted generated source.

`sources` requires seven scientific profiles with exact closed file counts: processor33, gaussian34, native22, reference13, kernel20, auditor35, original_auditor31. Required supporting profiles are adapter/executor/v6; optional protocol/bootstrap support profiles may carry original protocol bytes or the positively held ROOT bootstrap. Supporting profiles are1–128 explicitly pinned files. Their code is verified but not automatically imported by this adapter. Every preloaded non-stdlib bootstrap/support module must be within these closed source profiles so V6's preload check has positive authority. No generic extra-source or directory whitelist is introduced.

Each profile has exactly `directory,files,manifest,upload_manifest` as in V6. Directories are absolute, canonical, nonoverlapping and traversed nofollow. Exact files, modes0400, hashes, bytes and subdirectories must match. Optional upload manifests use only the established exact `parent_upload_manifest.private.json` exception and bind the complete files map. Manifest formats `files`, `members` or the full L-auditor's plain pin-map are understood. Every executable/source member must appear in the manifest. Only the manifest itself and specifically named checksum/allowlist metadata can be omitted from manifest entries; these remain independently pinned and read in the full ROOT profile. Unknown files, links, unmanifested code, count mismatches and source mutation reject before scientific imports. No source file is rewritten to accommodate a schema.

## Seven scientific role subjects

`role_subjects` is exactly operator/native_validator/reference/kernel/processor/protocol/numeric_state. Each value is an exact readonly file spec `{path,pin,mode:256}` belonging uniquely to one positively verified profile. operator and native_validator are the SAME original Gaussian34 and native22 manifest subjects; reference is the independent Lcore13 manifest; kernel is ARkernelV2's manifest; processor is the Lprocessor33 manifest. numeric_state is the exact processor/numeric_state.py file. protocol is the original frozen L protocol file or an identical copy positively included in a profile, whose bytes must equal processor/reference/PROTOCOL.md, reference/L_PROTOCOL.md and auditor/L_PROTOCOL.md. ROOT must preserve the historical semantic subjects, not substitute new directory inventory digests or individual model-file hashes for manifest hashes.

`original_source_pins` is the separately held old five operator/native_validator/reference/processor/protocol pins. operator/native_validator must equal the corresponding new subjects exactly. Old reference/processor/protocol stay historical, not relabelled as L. The adapter checks all required cross-copies: Lproducer's Gaussian/native/reference/kernel sources against their frozen groups; full L-auditor's original NumPy prior/packet/transport/digest/metrics/auditor/fixtures against original independentV2; and proper_core/ar_core across the independent reference, full auditor and producer reference copies. No copied producer original_processor.py is executed; its bytes remain covered by the whole first-clean Lproducer profile.

Execution config's semantic role names remain the ten described by the separate nine-stage control API: producer7 plus auditor/executor/adapters. ROOT maps those subjects to these filesystem groups and pins the loader config through its composite adapters/source authority. A filesystem profile named `gaussian` or `adapter` does not rename a historical semantic role.

## Loaded modules and lifetime

Producer order: native(marked_native,packet_io); gaussian(gaussian_operator,reference_core); reference(proper_core,ar_core); kernel(kernel); processor(numeric_state,l_math,descriptive,processor). Independent order: native only, then auditor(math_core,transport,packet_digest,packet,metrics,auditor,proper_core,ar_core,l_auditor). The independent path never imports producer, operator, kernel or Torch; it rejects preloaded or late producer modules from those profiles. Its observed runtime versions include Python/NumPy/SciPy only; Torch bytes remain bound by the external full runtime proof without importing Torch to inspect a version.

The unchanged V6 load_group executes only freshly verified source bytes under unique module names, temporarily sets the exact canonical aliases required by within-group imports, and restores previous aliases even on failure. Module file/unique identity and transitive native/prior/packet/codec/model aliases are checked. All numerical modules must share the guarded NumPy object; producer Torch globals must share the guarded Torch object. CPU environment must already specify CUDA_VISIBLE_DEVICES empty and OMP/MKL/OPENBLAS/NUMEXPR_NUM_THREADS=1. Producer sets Torch threads1 as the original loader did and checks CUDA is uninitialized. The adapter does not silently repair missing resource environment. Context exit rechecks CPU/global dependencies and deadlines; V6 restores original sys.path/meta_path.

Yielded dictionary exact keys: `mode,groups,source_pins,original_source_pins,observed_versions,adapter_config_pin`. Groups contain loaded modules by canonical names; source_pins has the seven verified semantic subjects. It contains no `verified=True` authorization receipt and no actual original admission or forecast values. Producer bindings and numeric codecs are available as modules, but ROOT's outer binder alone reads and positively decodes raw artifacts, constructs frozen processor.Bindings and audit authority, and supplies the execution library's binding receipt. No live module may be used after context exit.

## Verification scope
