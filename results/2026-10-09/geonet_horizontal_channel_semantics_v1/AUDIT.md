# GeoNet horizontal channel semantics: bounded source audit

GeoNet documents multiple horizontal label families. A parent-only check of already cached StationXML is therefore a useful next diagnostic; this packet does not identify replacement keys or authorize acquisition. Parent reports V5's fixed eight slots yielded six HTTP200 and two HTTP404 responses. That aggregate was not independently inspected here. A failed literal request does not establish an absent physical channel, and a successful response does not establish complete scientific usability. Preserve every V5 slot and outcome.

GeoNet's naming appendix distinguishes Z/N/E for north-aligned sensors, Z/1/2 for non-aligned sensors commonly used in boreholes or strong-motion recorders, and X/Y/Z for site-specific building arrays. U/V/W can describe non-standard orientations or mass-position monitoring. Historical exceptions remain. Its examples include HHN/HHE and HH1/HH2 for velocity, and HNN/HNE and HN1/HN2 for acceleration. Thus Z alone cannot identify the horizontal suffix family; the second character N denotes strong-motion instrumentation, not north orientation. [GeoNet stream conventions](https://www.geonet.org.nz/data/supplementary/channels)

GeoNet's station-service documentation includes a numbered-component example with horizontal dip and non-cardinal azimuths. It distinguishes channel descriptions, time ranges and sensitivity from complete response-level information; request time/channel filters restrict returned metadata. This establishes that numbered horizontal metadata occurs in GeoNet documentation, not that any selected station has it. [GeoNet FDSN documentation](https://www.geonet.org.nz/data/access/FDSN)

StationXML describes literal channel/location identifiers and channel epochs. Orientation, sample rate and response are optional; azimuth is clockwise from true north and dip zero is horizontal. Response information can describe conversion to physical units, but an empty response can represent unknown response. Optional DataAvailability is transient request guidance; Extent alone implies no continuity, and Span may be request-limited. These descriptions do not name or guarantee an S3 object. [FDSN StationXML reference](https://docs.fdsn.org/projects/stationxml/en/latest/reference.html)

GeoNet states that its AWS archive is synchronized daily and directs near-real-time users elsewhere. No inspected documentation binds a response epoch to a particular daily filename's existence. [GeoNet AWS access](https://www.geonet.org.nz/data/access/aws) The prior frozen authored writer-source audit independently pinned an official reader configuration, not a deployed writer. Reusing that syntax remains an unverified literal-key hypothesis; this audit neither reopens raw source nor upgrades that claim.

If the parent separately authorizes a cached-only inventory audit, the proposed check is:

1. Pin the existing cache bytes and custody first. Record its source, generation/retrieval dates, schema version, original request filters and level. A Z-only, station-level, restricted-time or otherwise partial cache cannot support a negative horizontal census. Missing query provenance or omitted channels means unknown, not absent.
2. At the same parent-fixed network/station/location and original study clocks, enumerate literal cached channel codes without renaming, trimming into aliases, substituting locations or extending time. Distinguish metadata presence from unique usable metadata across the entire requested window. Flag duplicate/overlapping epochs, missing bounds, boundary ambiguity or changes within a window; do not pick the latest epoch to resolve conflict.
3. Record each candidate's finite azimuth/dip, sensor association, nominal rate, response completeness, units and uncertainty independently. Preserve missing/conflicting fields. Declare any geometry tolerance and pairing rule before interpreting results. Never assume 1=N and 2=E, or rotate counts into cardinal components. Metadata-compatible labels remain descriptive candidates, not measured orientation or available waveform proof.
4. Retain separate fields for cache scope, epoch compatibility, orientation evidence, response evidence and literal transport outcome. Keep all four events and eight original slots in the denominator. A possible different literal family is a new prospective hypothesis requiring the parent's separate proposal, reviewed source/gate and explicit authorization, never a V5 retry, fallback or retrospective success.
