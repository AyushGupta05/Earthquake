If SIGALRM arrives after the inherited Fetcher increments self.bytes but before content.extend(chunk), its finally block records entry['bytes'] without that chunk. [P2] [P2] Handle UTC overflow independently of valid P evidence
origin.py:58
A timestamp such as 0001-01-01T00:00:00+01:00 parses successfully but raises OverflowError when lib.utc() converts it to UTC. Only ValueError is caught here, so an invalid origin time makes parse_row() throw and execute() replaces the entire row with parse_failed, discarding independently valid associated P coverage. The same overflow in a pick time escapes bulk.parse_row's P-parser catch and prevents independent origin extraction. Handle this conversion failure separately in both paths so it cannot erase the other evidence channel.

[P2] [P2] Use the generated-artifact ceiling when hashing outcomes
bulk.py:217
Finalization reads every generated file with a 128MiB ceiling, including outcomes.json. The response-body cap does not bound this file: accepted picks expand into indented JSON, and reused-tail outcomes add bytes outside the acquisition cap. A permitted run can therefore produce outcomes.json larger than 128MiB, causing finalization to raise before manifest.json is written. Use the separate generated-checkpoint ceiling or bounded streaming hashing for these artifacts.
