# Independent legacy semantic auditor v2

This authored, stdlib-only auditor independently interprets the public accepted-P contract and the inert, pinned GeoNet 0.10/0.11 XSLT texts. It may reuse only its own frozen v1 source; it does not read, import or copy any producer implementation. Development and review use invented XML only. Actual event bodies, IDs, plans, rosters, receipts, credentials, models and waveforms remain unopened. This is a new post-collection exploratory compatibility study of the parent’s unchanged six-event/eighteen-slot cached cohort, with zero new requests, clock changes or original-result edits. Those cohort aggregates are parent context, not evidence checked here.

The previous independent auditor in `../geonet_paired_semantic_audit/` remains frozen. V2 corrects its `newly_resolved_reference_count` label: an existing unique pick repaired for eligibility increments newly resolved without incrementing newly unique. V1 also used lexical weights where its producer used numerical signatures, and stricter recorded-revision evidence than its producer. V2 exposes lexical and finite binary-float signature diagnostics separately and documents the all-present-valid recorded-time guard. No actual V1 recovery claim was made; this version does not amend historical source or outcomes.

## Callable interface

```python
import semantic_audit
native = semantic_audit.project(native_bytes, event_id, "scml")
qml = semantic_audit.project(qml_bytes, event_id, "qml", profile="0.11")
comparison = semantic_audit.compare(qml, native)
```

`project(body: bytes, requested_event_id: str, format: str, profile: str | None = None) -> dict` accepts only caller-supplied UTF-8 bytes. `format` is exactly `qml` or `scml`; an optional profile is exactly `0.10` or `0.11`. Native root/version must agree and a supplied profile must match. QML root is QuakeML 1.2 with BED 1.2 fields. QML legacy fields require a caller-supplied profile independently bound by the parent to the paired pinned native root/version. An extension namespace does not infer authority or prove a deployed converter. Plain core QML permits profile `None`. Native versions/namespace aliases outside these exact profiles, mixed/foreign namespaces, contradictory profile, misplaced extensions and structural ambiguity stay unknown.

One body is limited to 4 MiB, 100000 elements and depth 64; the event-ID argument is a nonempty string of at most 4096 characters. DOCTYPE/ENTITY and non-UTF8 declarations are forbidden. Comments and processing instructions inside the document root are retained by the parser then conservatively unsupported; silently dropping them could merge scalar text across XSLT whitespace boundaries. XML declarations and comments outside the root do not alter field semantics and are permitted. There is no file reader, CLI, write, HTTP, AWS, subprocess, dependency install, schema validator or transform executor. Invalid caller types/format/profile raise TypeError/ValueError; unsupported XML returns `unknown_representation`. MemoryError is not converted to a success/zero. Parsing is byte-bounded; node/depth checks follow stdlib parsing. Pure functions do not enforce a wall deadline or aggregate output limit: a parent-owned process-group watchdog and bounded serialization are necessary before later actual inputs.

`compare(left, right)` takes two unmodified `project()` dictionaries in the same caller-trusted context. It is not a validator of fabricated dictionaries, source/input hashes or parent authorization. Unsupported projections return `available: false` and no denominators/recovery counts; valid empty denominators remain numeric zero. Caller-owned private raw metadata must never be placed in code review or published merely because the function produced it.

## Semantics

Native scope follows event originReference nodes exactly, including literal raw text after XSLT whitespace-only removal. Preferred origin must belong to that scope. Picks are selected through arrivals of every referenced origin plus stationMagnitude→amplitude→pick paths, while accepted-P denominators use only the preferred origin. Arrival scalar/vocabulary validation covers every event-scoped origin in both representations. An amplitude lacking its amplitude child can scope a pick while having zero source-derived emission count. Shared amplitude references preserve emission/path multiplicity. Missing/ambiguous origins/amplitudes, duplicate non-pick scoped identities, scoped cross-type ID reuse and distinct-raw native mapping collisions are unknown. Duplicate pick objects remain unresolved reference lower bounds rather than choosing a record. Outside-scope native origins/picks are annotated separately. Outside objects never expand selected scope, but shared raw or candidate publicID with a selected object remains unknown, including wrong-type global objects and magnitudes. PublicID ambiguity is checked across the whole document against selected objects; ordinary selected duplicate picks still remain unresolved lower bounds. This is narrow relation parsing, not whole-schema conformance.

Raw IDs and candidate mapping are distinct. Native convertID preserves literal `smi:`/`quakeml:` prefixes; otherwise it prefixes `smi:nz.org.geonet/` and translates ASCII spaces/colons to underscores. Optional ID nodes use `NA` for an empty value. Object attributes never use that fallback. Missing/empty/NA object identities cannot establish correspondence. Candidate creationInfo maps agencyURI/authorURI with the optional-ID rule and retains native nonblank lexicals; raw creationInfo is also returned. Native preferred-origin, arrival and amplitude scope uses raw identity before QML reference text is stripped. Native event identity must equal the supplied literal requested ID before noninjective mapping. A raw arrival reference cannot resolve to a separately amplitude-selected trimmed-ID pick; it stays unresolved even if projected reference trimming would match. Raw/projected target identity multisets and reference stripping are compared independently of uniqueness; duplicate or absent targets cannot hide a mapping disagreement. Mixed native/QML arrival weight vocabularies are unknown.

Native weight/use expectations follow exact XSLT `true`/`1` tests. Raw absent/true/false/unrecognized use flags remain separate. Present weight copies to timeWeight when timeUsed is exactly true/1 or all three flags are absent; absent weight with timeUsed true/1 emits 1; other cases emit no timeWeight. Slowness/backazimuth candidates are also returned as diagnostics. P acceptance is exactly case-sensitive P/Pg/Pn/Pb, unique referenced pick resolved before weight rejection, missing/empty or positive finite binary-float timeWeight (including underflow rejection), status other than stripped lowercase rejected, nonempty stripped station/network, valid aware time, then accepted-ID dedup. Exact native reported status is suppressed only in the candidate while raw reported is retained. NZ means uppercase NZ exactly. Location/channel attributes remain literal. Timestamp syntax follows Python 3.14 datetime.fromisoformat with Z replacement, timezone required, UTC microseconds; its broader syntax and fractional truncation are not schema validity assertions.

The separate curated XSD addendum overrides the older proposal’s unverified 0.10 passedQC fallback: 0.10 passedQC is unsupported/unknown under both native and BED placement. The conditional XSLT fallback remains documented. In 0.11, passedQC is supported only at native origin/stationMagnitude or the exact 0.11 extension under BED event/stationMagnitude. Its singleton scalar must be true/false/1/0 after XML whitespace collapse, with raw text retained. modificationTime is a singleton only under exact creationInfo: native own namespace or the explicitly bound profile extension under BED creationInfo. These are metadata; passedQC does not affect P eligibility. Full XML schema validity remains false.

Comparison requires exact mapped event/preferred identity, no native raw-to-projected reference ambiguity, complete equal preferred origin time/latitude/longitude/depth (native km→m), lexical arrival multiset match, consistent profiles and no known creationInfo lexical conflict. Decimal normalization is context-free and exact: invalid/nonfinite remains null, tiny nonzero never becomes zero. `arrival_multiset_finite_canonical_match` is a separate nullable finite binary-float-hex diagnostic and never promotes lexical disagreement. Equal event+origin creationInfo and at least one recorded timestamp, with every present timestamp nonempty/valid/aware, permit `matching_recorded_revision`; any known lexical field conflict blocks it. This is not an atomic database revision guarantee.

Recovery measures distinct left qualifying reference IDs. `newly_unique_reference_object_count` counts IDs newly associated with exactly one right pick object. `newly_resolved_reference_count` counts qualifying-left IDs accepted right but not accepted left across all networks. `newly_accepted_NZ_reference_count` intersects those newly accepted IDs with right accepted NZ IDs. Existing-object repairs can increment the latter two while unique recovery stays zero. `content_matched_resolution_candidate_count` guards the NZ count by content/profile/identity/revision consistency; `paired_recorded_revision_resolution_count` additionally requires matching recorded revision evidence. Raw recovery counts before the guards are diagnostics only. They never prove physical picks, converter defects, operational availability, atomic DB revisions, novelty, EEW performance or model improvement.

## Output shapes and limits

See `PUBLIC_SCHEMAS.md` for fields. A positive NZ subset can set NZ_coverage_known while incomplete_associated_P_structure is true; that means observed subset coverage, not full denominator completeness. Missing/duplicate references and rejected eligibility remain explicitly separate. Counts preserve unresolved lower bounds. Unknown representations retain null denominators and accepted objects, not zero.

Source-policy differences are deliberate and must be reported by the parent instead of claiming agreement: this auditor preserves unrecognized native use-flag text and applies the source’s exact literal branches, whereas the public legacy producer protocol rejects unrecognized boolean lexicals; this auditor’s exact Decimal geometry can remain known where stricter finite binary-float geometry would be unknown. These cases do not certify full accepted-predicate agreement. No automatic normalization or alias is allowed to manufacture comparison agreement. The original producer’s numerical signatures/any-valid revision timestamp policies are superseded only for this separately versioned study, never retroactively.
