## Exact public source contract

GeoNet's published FDSN handler reads the stored QML event representation and separately exposes stored original SCML through `/sc3ml`. Published routes and the documented service host motivate the two URLs; deployed proxy/build availability remains unverified. Current handler source rejects `includeallorigins`, `includearrivals` and `includeallmagnitudes`; only eventid is used. No published route proves that missing objects exist in either representation. The original source-only audit and proposal remain preserved separately.

Both supported transforms are pinned to GeoNet/fdsn commit `3040322c7bf0818c9b42a6666284b86f674cb706` in public_transform_pins.json. These are read as text, never executed or imported. Native SCML requires matching namespace and version: 0.13 uses `http://geofon.gfz-potsdam.de/ns/seiscomp3-schema/0.13`; 0.14 uses `http://geofon.gfz.de/ns/seiscomp-schema/0.14`. The published ID rule preserves identifiers beginning `smi:` or `quakeml:`. Other IDs receive `smi:nz.org.geonet/` and each colon or space becomes underscore. Exact mapped event and preferred origin linkage is required, with native preferred origin in the event's originReference list. Native origin objects are restricted to that event's originReferences; native pick scope follows arrivals in those origins plus their stationMagnitude->amplitude->pick links. Unrelated global picks do not supply event evidence. Mapping collisions involving the event, referenced origins, scoped picks or scoped amplitude identities/references, foreign structural namespace substitutions, duplicate singleton fields, ambiguous/missing referenced origins and unsupported versions are unknown representations. Duplicate pick objects remain unresolved qualifying references, never choose-first objects. Depth km is projected to metres; no other geometry is substituted.

Native object scope uses literal raw IDs. After source mapping, the frozen QML predicate strips projected reference text while leaving mapped publicID attributes literal. A preserved URI ending in whitespace can therefore remain an unresolved pick reference; an unresolvable projected preferred-origin reference makes the representation unknown. Invented fixtures verify this distinction.

For each native arrival, weight is projected to QML timeWeight exactly as the pinned transform specifies: retain supplied weight if timeUsed=true/1 or all three use flags are absent; set1 if weight is absent and timeUsed=true/1; otherwise omit timeWeight. Native weight and flags are also retained privately. The frozen QML predicate accepts missing or empty timeWeight. Thus a native timeUsed=false can still produce missing QML timeWeight and be accepted by this **projected QML-equivalent** predicate; that is not an assertion the native arrival was used physically. Qualifying P/Pg/Pn/Pb references are resolved uniquely before weight rejection, followed by rejected-status, network/station and aware-time checks, then accepted-ID deduplication. Missing-reference, invalid-time and missing-station incompleteness retains the original semantics. ## What comparison establishes

Private outputs compare original-vs-fresh QML for catalogue drift, and fresh-QML-vs-native SCML for representation differences. They retain exact mapped event/preferred-origin identities, origin UTC microsecond/finite geometry values, preferred-arrival multisets and each available event/origin creationInfo field. Missing origin fields give unknown content match. Known conflicting revision fields prevent content-matched resolution claims. Equal recorded creation/modification timestamps with equal creationInfo support only a recorded-revision match; no atomic database revision is verified. Lexical creationInfo differences, unusual decimal/float serialization and unsupported XML stay conservative diagnostic limitations. Recovery counts distinguish newly unique objects from newly accepted references.

Newly accepted references are qualifying left-side P references accepted on the right but not on the left. This includes an existing unique pick gaining valid time or station metadata; it need not be a newly unique object. Content/revision claim restrictions still apply independently.

CreationInfo retains agencyID/agencyURI, author/authorURI, creationTime/modificationTime and version text exactly. Matching-time evidence additionally requires a nonempty valid aware timestamp. The pinned transforms explicitly retain native modificationTime as a SCML namespace extension under BED creationInfo; only that exact parent/field and either supported SCML namespace are allowed, with a unique singleton across namespaces. Other foreign evidence fields remain unknown. URI fields are retained lexically for conservative comparison; source URI normalization can therefore cause a conservative conflict, never an unsupported recorded-revision match.

Decimal canonicalization traps inexact arithmetic. A nonzero value that would silently underflow during depth scaling or normalization gives an unknown geometry field, preserving the event and pick denominators while preventing a false content/revision resolution claim. Exact subnormal values remain distinct from zero.

Each representation gets its own accepted-subset T0, all-network/NZ counts, strict `<T0+h` station counts at h=1/3/5, and shadow counts at the preserved original accepted-subset NZ clock where available. That preserved clock comes from the checksum-bound original census base outcome and stays available even if the stricter original shadow parser is unsupported. Recovering an earlier pick can change an independently recomputed T0 and reduce relative counts. No automatic re-clock is applied. A matching-record resolution candidate does not prove a conversion bug, physical onset validity, operational receipt timing, novelty or magnitude improvement.
