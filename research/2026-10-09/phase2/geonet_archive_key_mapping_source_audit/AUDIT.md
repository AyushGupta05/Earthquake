# GeoNet daily archive key mapping: source-only audit

The official GeoNet tutorial verifies the daily key layout. **UTC filename boundaries and blank-location filename encoding remain unverified in the narrow official source trail inspected here.** The official FDSN code provides related UTC/header/query evidence, which supports hypotheses but does not prove how the public archive keys are generated.

This documentation-only audit read official public docs and inert GeoNet-authored code. It made no waveform, station/event metadata, data-object, archive listing, bucket, account, FDSN/API, or cloud queries; executed no raw source code; installed nothing; changed no shared Git or frozen processing source, tests, reviews, or manifests. Public-source HTTPS retrieval is recorded separately. This packet creates no acquisition authority.

## Falsifiable candidate hypothesis; no execution permission

`mapping_hypothesis.json` preregisters a candidate shape. For an independently pinned aware time, **hypothesize** converting to UTC before deriving Gregorian year and three-digit DOY. Preserve an independently pinned nonblank location literally when it already fits the tutorial's two-character uppercase shape. Do not silently uppercase, strip, pad, truncate, or substitute values to force a fit.

For a blank location, the verified mapping status stays unknown. The conservative documented-subset option is to exclude blank-LC slots from mapping-certified use. If a later separately authorized experiment requires a blank candidate, preregister the sole uncertain empty-field variant (`…[CHA]..D`) and label it `blank_location_filename_hypothesis`. Empty input, two spaces, `--`, and `00` are distinct values; this audit authorizes no equivalence or fallback between them. Do not try alternate aliases in response to failure without a separately versioned/authorized design.

An invented UTC boundary example is `2020-01-01T00:30:00+13:00`: the UTC hypothesis selects year2019/DOY365; a local-calendar rule selects year2020/DOY001. This demonstrates a discriminating prediction without constructing or requesting an actual key. Later authorized content/header checks could test which day partition and blank identifier the selected object represents. An HTTP success alone cannot do that.

For a four-slot anonymous transport preflight, pin all four literal candidate addresses and their hypothesis labels before any request. A positive response supports access/existence for that exact literal address at that observation; it does not prove the requested NSLC/day or general mapping. A verified `NoSuchKey` under the chosen endpoint/access conditions contradicts the exact candidate's existence there; a denied/ambiguous/error response cannot diagnose timezone versus location versus missing coverage. A negative candidate does not prove no waveform exists under a different key. Four responses cannot estimate general archive completeness or retrospectively verify arrival availability, EEW feasibility, latency, model improvement, or physical timing. No such requests were made by this audit.
