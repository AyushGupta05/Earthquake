# GeoNet association-clock completeness: primary-source audit

Published GeoNet source provides a plausible alternative representation to inspect in a separately authorized metadata phase, but **no source reviewed here proves recovery of the unresolved picks**. Keep the frozen counts96 roster, accepted-subset clocks, masks and requests unchanged. No event query, event refetch, outreach, code execution or model work was performed for this source audit.

## What the current evidence establishes

[GeoNet's catalogue documentation](https://www.geonet.org.nz/data/types/eq_catalogue) distinguishes basic QuakeSearch preferred solutions from detailed QuakeML, including pick and arrival information. [Its FDSN documentation](https://www.geonet.org.nz/data/access/FDSN) gives an eventid-only QuakeML query example; its event parameter table does not list includeallorigins or includearrivals. A description of detailed/full metadata does not certify every referenced pick resolves uniquely in each returned body.

The [FDSN event 1.2 specification](https://www.fdsn.org/webservices/fdsnws-event-1.2.pdf), its optional-parameter table, makes includeallorigins and includearrivals optional service parameters with false defaults, subject to center behavior. Their existence in the standard does not demonstrate GeoNet support. Text output cannot substitute for the arrival-object representation. An attempted web read of GeoNet's application.wadl was unavailable; no flag or event query was attempted.

Stronger implementation evidence is the official GeoNet/fdsn repository, pinned to 3040322c7bf0818c9b42a6666284b86f674cb706. [fdsn_event.go](https://github.com/GeoNet/fdsn/blob/3040322c7bf0818c9b42a6666284b86f674cb706/cmd/fdsn-ws/fdsn_event.go), lines 66–75 and 203–205, explicitly rejects the presence of includeallorigins, includeallmagnitudes and includearrivals. Lines 330–351 and 525–547 select stored Quakeml12Event fragments and wrap them in QuakeML; the handler does not resolve missing pick objects through a separate lookup. This pins published behavior, not the deployed service's build identity. Adding optional flags is therefore not an earned repair strategy.

## Official alternative representations and their limits

[The consumer's sc3ml.go](https://github.com/GeoNet/fdsn/blob/3040322c7bf0818c9b42a6666284b86f674cb706/cmd/fdsn-quake-consumer/sc3ml.go), lines 54–55 and 193–196, preserves its received SCML string separately from an XSLT-derived QuakeML event fragment. The conversion dispatch recognizes SCML versions 0.6–0.14. Two current transform assets were inspected as text below; no transform was executed. Omission during conversion remains a hypothesis, not an observed cause. [Consumer main.go](https://github.com/GeoNet/fdsn/blob/3040322c7bf0818c9b42a6666284b86f674cb706/cmd/fdsn-quake-consumer/main.go), lines 183–195, fetches a notified S3 object and saves the parsed representation; this is not proof that the upstream object contains every required pick.

[routes.go](https://github.com/GeoNet/fdsn/blob/3040322c7bf0818c9b42a6666284b86f674cb706/cmd/fdsn-ws/routes.go), line 45, registers a /sc3ml route. [That handler](https://github.com/GeoNet/fdsn/blob/3040322c7bf0818c9b42a6666284b86f674cb706/cmd/fdsn-ws/sc3ml.go), lines 11–25, accepts eventid and selects stored Sc3ml by public ID. Thus the published server offers an original-format representation of its stored record. No live availability, response schema, revision match or reference-resolution improvement was verified. An SCML export can itself remain incomplete; the handler performs no pick recovery.

The pinned [SCML0.13](https://github.com/GeoNet/fdsn/blob/3040322c7bf0818c9b42a6666284b86f674cb706/cmd/fdsn-quake-consumer/assets/sc3ml_0.13__quakeml_1.2.xsl) and [SCML0.14](https://github.com/GeoNet/fdsn/blob/3040322c7bf0818c9b42a6666284b86f674cb706/cmd/fdsn-quake-consumer/assets/scml_0.14__quakeml_1.2.xsl) transforms collect event-referenced origins and their existing referenced pick objects. They normalize IDs; equality requires the documented mapping and collision checks. SCML0.14 also derives timeWeight from weight/use flags, sometimes omitting it. This supports checking both object linkage and native flags, not treating every missing QML weight as a known native weight. No actual event was inspected, and older transforms were not audited.

The official [qsearch README](https://github.com/GeoNet/qsearch) describes detailed preferred-origin arrivals/picks. Its audited main commit 14215d6b999df5e903c073e7ef9df0cdb198f0fe dates to 18 November 2016. [qsearch.go](https://github.com/GeoNet/qsearch/blob/14215d6b999df5e903c073e7ef9df0cdb198f0fe/qsearch.go) actually uses the seiscompml07 package for detailed output. [seiscompml07.go](https://github.com/GeoNet/qsearch/blob/14215d6b999df5e903c073e7ef9df0cdb198f0fe/seiscompml07/seiscompml07.go), line 14, names a historical static SCML endpoint; lines 247–248 link each arrival to the pick map by ID. It does not independently retrieve a missing pick. The sibling [quakeml12.go](https://github.com/GeoNet/qsearch/blob/14215d6b999df5e903c073e7ef9df0cdb198f0fe/quakeml12/quakeml12.go), lines 14 and 226–227, uses an older QuakeML endpoint and the same reference lookup. Neither qsearch execution nor any endpoint fetch was attempted. Historical source cannot establish a current recovery service.

[SeisComP scxmldump documentation](https://www.seiscomp.de/doc/apps/scxmldump.html), version 7.4.0, distinguishes event/origin export, associated-pick inclusion via with-picks, arrival exclusion via ignore-arrivals and preferred-only selection. This establishes that exporter configuration can alter included objects. It does not identify GeoNet's actual exporter invocation, explain the observed omissions, establish missing objects exist in its database, or grant database access. A database-backed export is not a public resolution API demonstrated here.

## Aggregate planning consequence; no new gate

The existing independent [completed495 summary](../geonet_bulk_independent_audit/completed495_summary.json), SHA256 e3c8bd56dcfe2a316f3e1ec8747d7c40602f35a681b053d2a077eb9053dd59f7, reports 22 incomplete tail subsets, all in 49-event candidateTEST. Band denominators are 30/14/5 for [5.5,6)/[6,7)/>=7; incomplete counts are 18/3/1. If a future primary protocol required every qualifying association to resolve and excluded all these flagged events, conditional complete-reference ceilings would be 12/11/4 by band, 27 for Mw>=5.5 and 15 for Mw>=6, before waveform or sequence attrition. The 27 ceiling falls below the proposed 30 TEST Mw>=5.5 floor. This is arithmetic under a hypothetical policy, **not an approved exclusion, observed repaired count or reason to edit counts96**.

The [aggregate diagnostics](../geonet_bulk_independent_audit/completed495_extra_diagnostics.json), SHA256 b98c5971c1cad5eb17c3fe065eaa195b10631706b2e9c956f0dc2348c99056b6, contain 707 missing-or-ambiguous qualifying pick references in the 149 tail events. That combined reason does not distinguish omission from ambiguous identity, export settings from transform behavior, or an upstream absent object from a recoverable one. No cause of the TEST concentration is demonstrated.

## What a later no-fit recovery diagnostic would need

A separately frozen, bounded paired metadata phase would need to establish the alternative endpoint and schema, pin both raw representations and request receipts, and compare the same event identity, preferred-origin identity/revision, origin time and qualifying arrival associations. Recovery means a formerly unresolved reference becomes a unique, valid pick with required time and station identity while preserving the original phase/weight/rejection rules. A changed preferred origin or newer catalogue revision is a different record, not a representation-only repair; preserve that distinction. Compare unresolved counts and all three recalculated clocks/masks, without choosing favorable replacements or editing the existing artifact.

Invented counterexample: the resolved subset contains station A at 100.0 s and station C at 100.8 s, so old T0=100.0 s and its strict 1 s view has two stations. If the unresolved station B pick is recovered at 99.0 s, complete T0=99.0 s and the strict 1 s view contains B alone; A exactly at 100.0 s is excluded. Adding resolved objects need not increase counts after changing the clock. Existing count lower bounds apply at the preserved accepted-subset T0, not at an inferred fully resolved earlier T0.

Even a successful catalogue repair would not reconstruct operational picker, packet receipt or warning latency. Metadata recovery requests require a separate frozen plan; no fit is earned by this source sketch. Current frozen counts acquisition may proceed only through its existing parent-owned protocol and controls.
