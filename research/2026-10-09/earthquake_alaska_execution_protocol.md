# Alaska: gains, clocks and an executable comparison

**A causal released-archive adaptation is feasible. An exact EPIC replay or an annotated first-P benchmark is not yet reproducible from this release alone.** This audit read all `.dat` metadata, existing v2 header results and public source text. It decoded no waveform samples, ran no model and changed no header outputs. Proposed choices below are not author settings or implemented preprocessing.

## What is actually supplied

All 781 metadata files declare ten columns: `network station location channel latitude longitude elevation samplerate gain units`. All 296,990 rows follow that layout. There are no event-origin times, station P picks, pick declaration times, sensitivity reference frequencies, response stages/poles/zeros, azimuths, dips or quality labels. The release ZIP contains only these files and MiniSEED; no replay logs, executable, parameter file or event catalog. See `metadata_fields_audit.json`, including member hashes and exact examples.

`DU/M/S` accompanies all BH/HH channels (206,024 rows); `DU/M/S**2` accompanies all BN/HN channels (90,966). The appropriate scalar conversion is **recorded digital counts divided by the event-specific channel gain**, yielding sensitivity-scaled m/s or m/s², respectively. Never multiply by gain, treat both families as velocity, or apply scalar correction twice. This is not full instrument-response deconvolution. [FDSN specifies sensitivity as scalar system gain with a reference frequency, separately from response stages.](https://docs.fdsn.org/projects/stationxml/en/latest/reference.html#instrumentsensitivity)

A bounded independent [EarthScope response query](https://service.earthscope.org/fdsnws/station/1/query?network=AK&station=BRLK&location=--&channel=BHZ%2CBNZ&starttime=2010-01-25&endtime=2010-01-26&level=response&format=xml&nodata=404) exactly confirms the release's two AK.BRLK vertical gains for 25 January 2010: BHZ 627,366,000 counts/(m/s), valid at 0.3 Hz; BNZ 427,894 counts/(m/s²), at 0.09 Hz. This checks the convention, not every station epoch. XML SHA-256 is `c95a5734969873bea626d38e1f59c8a58fb48fc76760c624d9b6f1e84f2189bd`. Freeze response metadata if it is later used; do not replace the release's historical gains with current station settings.

There are 98,424 complete E/N/Z instrument groups and 1,571 incomplete groups, where a group is `(network, station, location, two-letter channel family)`. Complete groups have consistent metadata coordinates/rates. Of these, 68,242 are velocity groups, spanning every release container (5–247 groups/event); 30,182 are acceleration groups. Different locations/families must not be stitched into a fictitious triplet. Channel letters identify the supplied component labels; exact geographic rotation is not established without orientation metadata.

## EPIC source boundary

The [Alaska paper's methods](https://doi.org/10.1785/0120260139) describe tank-file replay, automatic triggers and evolving logs. Reported settings include a 400×400 km grid, ak135 travel times, fixed 8 km depth, at least four unique stations, one within 200 km, and Kuyuk–Allen peak-displacement scaling. It describes requested recordings from origin−180 to +420 s. It does not supply the precise waveform-processor filters, trigger thresholds, all quality gates, versioned replay executable or full configuration. The downloaded supplement adds no such configuration. These facts do not establish an executable replication.

The public [bEPIC repository at commit `2bd91ebffd9739471629df97ac6f18e2b60d1261`](https://github.com/amy-l-williamson/bEPIC/tree/2bd91ebffd9739471629df97ac6f18e2b60d1261) consumes existing EPIC trigger/log-Pd tables (`data_util.py`); it does not create them from MiniSEED. Its `magnitude.py` uses `1.23 log10(Pd)+1.39 log10(R)+5.39`, distance rejection and an unweighted mean. Do not label this script the complete Alaska EPIC implementation. Its tree has no license file; downloaded files are retained as read-only research references, not vendored implementation. No scripts or embedded network-log retrieval paths were executed.

## Clock decision

| Clock | Reproducible information | Interpretation |
|---|---|---|
| Current catalog origin +1/3/5 s | Frozen ComCat snapshot and sample UTC headers | Source-time diagnostic; origin is retrospective side information. Often precedes useful station arrivals. |
| Annotated station P +1/3/5 s | Not provided | Cannot claim this benchmark from filenames or a fixed sample index. Offline future-assisted picks require an explicit oracle label. |
| Theoretical P +1/3/5 s | Requires catalog hypocenter and a pinned travel-time model | Arrival oracle; useful only as a separately labelled sensitivity study, not an operational clock. |
| Causal detector declaration +1/3/5 s | Must be generated by a frozen streaming detector | Recommended implementable clock, explicitly called **time after automatic trigger**, not time after true P. |

Header/current-ComCat alignment is typically origin−120 to +240 s: median channel start/end offsets are −119.9916003/+239.9923930 s. The paper's longer requested window is not a safe indexing rule. The v2 output also contains very short traces. `clock_and_components_header_diagnostic.json` preserves every event's offsets; it reads no arrival values. All containers have at least one complete triplet spanning source origin through +5 s, which does not imply a P wave has arrived.

For a first causal pilot, freeze a common vertical-channel detector before scoring Alaska: 100 Hz causal stream, 4th-order 1–20 Hz Butterworth SOS, zero initial state, recursive squared-amplitude STA/LTA with 0.5/10 s time constants, 30 s uninterrupted warm-up, on/off ratios 4/1.5. [ObsPy documents the recursive STA/LTA primitive](https://docs.obspy.org/packages/autogen/obspy.signal.trigger.recursive_sta_lta.html); the settings here are an explicit proposed control, not an EPIC recreation. Keep recurrence/filter state across chunks. A threshold crossing's actual declaration time is the clock. Use the earliest declaration in the replay, retaining noise-triggered and no-trigger cases; never retrospectively replace it with the most plausible catalog-matched or highest-SNR pick. Catalog matching is for scoring only. Store all trigger candidates and the detection status so conditional magnitude error cannot conceal detection failures. This event-window exercise cannot estimate continuous-network false-alarm rates.

## Fixed input and comparison rules

- Start with sensitivity-scaled **velocity** triplets for all learned controls; retain acceleration as a separate declared extension requiring causal integration/response handling. Keep each event even if a particular forecast has no usable stations. Count unavailable outputs separately. Use no true magnitude/depth/distance for station selection.
- Within a physical `(network,station)` use a fixed metadata-only sensor priority: BH before HH, then blank location before lexical remaining locations. Fix that choice before waveform inspection; if its data are absent at a cutoff, mark it absent rather than selecting a later-complete instrument. This avoids counting co-located instruments as independent stations.
- For the current 25-station TEAM port, fix up to 25 sites at the first declaration `τ`, ordered by distance to that triggering station (ties by network/station). The reference is an observed station coordinate, never the future earthquake location. Keep those sites at all three horizons and apply the same cap to pooling/distribution controls. This is a declared adaptation; report available-station counts.
- Accept finite positive gains and known unit families only. Use exact header rates/timestamps; keep the 833 nonexact rates, with their recorded deviations. Build a 100 Hz stream with causal native-rate low-pass filtering and previous-sample interpolation; no future interpolation sample, forward-backward filter, whole-trace demeaning, endpoint reflection or retrospective time shift. A missing interval longer than 1.5 native sample periods breaks state and requires new warm-up. Preserve resampling/filter delay in declaration time.
- At deadline `τ+h`, only samples at or before that UTC may enter the detector, normalization, amplitude summaries, station mask or model. Use identical station identities, masks, gains, coordinates and waveform tensors for TEAM-LM, matched pooling and the distribution variant. Append a missing-data mask rather than declaring padded zeros observed. Test that extending the replay leaves earlier tensors/triggers/predictions unchanged.
- Freeze preprocessing/model settings on the original training data, not Alaska outcomes. Retrain/adapt all controls together if input filtering/scaling changes; a counts-trained INSTANCE checkpoint cannot simply consume physical velocity and remain a fair transfer control. Compare event-macro point/proper scores and coverage under the same clock; a paper's final EPIC number is not a same-input 1/3/5-second result.

For **exact EPIC** comparison, the missing deliverables are the replay binary/source version, complete parameter files including waveform processing, tank conversion/replay scheduling, and resulting trigger/solution logs. For **true-P** comparison, the missing deliverable is a pinned arrival table with picker method, allowed context and declaration times. Neither can be inferred from `.dat`. Continue with the explicitly named released-archive adaptation if these remain unavailable; preserve all 781 container identities grouped into the 780 known catalog identities, and never choose a geographic/quality cut to force 530.
