# Concrete ROOT primitives: private configuration schema

Source-only schema. Actual documents/values stay private and never enter review.
Every spec below is exactly `{path: absolute canonical path, pin:{bytes,sha256}, mode:256}` unless an explicitly live OS path is stated. All JSON documents are canonical, reject duplicate keys/nonfinite numbers, and are independently pinned by the already held ROOT composition. No evidence document contains its enclosing ROOT pin (which would introduce a hash cycle).

`make_primitives(held, *, expected_root_pin, root_spec, modules, source_begin, clock)` returns `(Primitives, Custody)`. Its constructor authenticates ROOT raw bytes against the external expected pin before following any private spec. Primitives contains the five exact root-glue methods. `primitives.retain_return` is the concrete durable retainer for `root_glue.run_parent`.

The five existing evidence roles retain their root-glue locations. Projection is unchanged. Documents below are proof formats, never Boolean verification requests.

* `source_runtime`: `{schema:'root-L-source-runtime-proof-v1', execution_pin,loader_pin,runtime_spec_pin,source_pins,boot_id}`. Runtime spec pin is the canonical full loader runtime object. Boot ID is the actual current Linux boot UUID. Source profiles, manifest/copies/module identities and the frozen10112-file runtime/vendor/generated/metadata proof are verified using frozen source primitives; this document does not replace them.
* `current`: `{schema:'root-L-current-proof-v1', execution_pin,boot_id,expires,retention_directory,timer,resources,storage}`. `timer` is `{unit,service,exec_start,deadline}`; timer names are ROOT-held own names, `exec_start` is the exact previously independently checked `systemctl show` service ExecStart value; deadline is the same-host monotonic installed whole-stop deadline <=whole_begin+7400. Frozen bounded transport re-reads actual timer/service properties, eligible next expiry and boot ID. `resources` is a readonly spec for `{schema:'root-L-resource-reservation-v1', execution_pin,boot_id,whole_begin,science_deadline,closure_deadline,expires,limits}`; limits is exactly frozen control.LIMITS. `storage` is a readonly spec for `{schema:'root-L-storage-reservation-v1', execution_pin,directory,reserved_bytes,minimum_free_bytes}`; directory is the actual child journal and reserved_bytes=9*64MiB. Actual filesystem free space is re-read.
* Funding document: `{schema:'root-L-funding-reservation-v1', scope,expires,task_ceiling_cents,reservation_cents,spent_upper_cents,future_upper_cents,eligible_credit_cents,other_reserved_cents}`. Integer cents only; no duplicate prior reservation; spent+future<=reservation<=45000, task ceiling<=200000, eligible credit minus other reservations covers future. This is a ROOT-held independently checked resource authority, not an AWS query or proof of settled spend. The cap is the newly authorized maximum, not a report of actual balance or spend.
* Publication document: `{schema:'root-L-publication-authority-v1',scope,expires}`. Funding/publication scope is exactly `{experiment_id,whole_begin,lease_deadline,source_pins,runtime_pin,input_pins,protocol_pin,storage_limit_bytes,study}` from the held execution, excluding the document pins and execution pin to avoid a hash cycle. ROOT must issue/pin publication only after source review, publication and real-runtime invented checks; source/runtime bytes are separately reconstructed, not accepted from its requested hashes.
* `inputs`: `{schema:'root-L-input-proof-v1',execution_pin,loader_pin,facts,projection_pin,original_execution,independent_returns,native_receipt,initialization_receipt,comparator_receipt}`. `original_execution` is the actual raw independently held `root-marked-original-fourteen-execution-v1` metadata spec, not a rewritten14-stage summary. `independent_returns` is seven ordered actual raw `root-seven-audit-last-return-v1` specs. Complete original14 and independent7 directory inventories, manager streams, zero exit, exact last-return/closed equality, request/child/report/result pins and OS cleanup are rechecked before native/numeric decode. Failure markers/unknown members or missing custody reject.
* Three held receipts each are `{schema:'root-L-held-<kind>-receipt-v1',subjects,source_pins,original_source_pins,closure}` for kind native/initialization/comparators. `closure` is a readonly spec for independently retained raw ROOT verification evidence, not a self-declared digest. `subjects` is respectively `{feature_archive,feature_manifest,feature_authority}`, `{original_admission,original_admission_authority}`, or `{closed_comparator_report,comparator_origins,comparator_authority}`, each equal to its independently held input pin. Closure JSON must contain exactly `{schema:'root-L-independent-input-check-v1',kind,subjects,source_pins,original_source_pins,packet_sha256,original_execution_closure_sha256,evidence}`; evidence is a nonempty exact map of readonly specs to the underlying raw completed checks. ROOT must hold those receipt pins independently after executing the checks. Status flags are not a substitute for those raw receipts and actual21-stage custody.
* `audit`: `{schema:'root-L-audit-proof-v1',execution_pin,input_evidence_pin}`. It binds the previously authenticated whole inputs proof. Audit true flags are produced only after rechecking the exact prior actual-return custody plus L admission,300-step/optimizer/final-probe retention, or two independently closed66-record audit reports as applicable. No caller-provided audit-authority candidate is trusted.

Final additions before first review: funding additionally requires `eligibility` readonly spec; resources additionally requires `quota` readonly spec. Eligibility is `{schema:'root-L-credit-window-v1',scope,expires,eligible_services,raw_credit_readback}`; scope is STATIC_SCOPE above, service list must explicitly include `Amazon Elastic Compute Cloud`, and raw_credit_readback is the exact independently reviewed ROOT provider-credit record as a resolvable readonly spec. Provider-specific eligibility/balance interpretation stays ROOT's responsibility; this parser does not manufacture provider truth or a hard credit reservation. The record is read/hash/JSON checked and retained.

Quota is `{schema:'root-L-quota-window-v1',scope,expires,limit_vcpu,used_vcpu,additional_vcpu,resource_readback}`. Limit is16; additional is0 (existing host, CPU-only, no provider allocation). resource_readback resolves the actual `{schema:'root-scoped-aws-readonly-refresh-v1',checked_utc,no_resource_start_or_change,raw}` envelope. raw has exactly account/instances/owned_volumes/quota/running_G_VT. quota is standard AWS `{Quota:{Value:16,...},...}`. running_G_VT must be the complete standard DescribeInstances JSON object with Reservations/Instances, CpuOptions, InstanceType and State, no unconsumed NextToken. Used vCPU is reconstructed from active G/VT CoreCount*ThreadsPerCore and must equal used_vcpu and fit the16 limit. No AWS API is called by this code. The explicit ROOT reservation window and each-stage expiry checks authorize using this observation; they are not a claim that a shared provider quota or credits are physically reserved.

The initialization closure's evidence.original_execution spec must equal inputs.original_execution. facts.original_execution_closure_sha256 always identifies those original14 metadata bytes; it never identifies the new wrapper or its closure and introduces no self-reference.

`documents.root_context` is not interpreted as an authority by this implementation. It remains the exact ROOT-scoped context document checked by glue. ROOT's real protocol document remains the pinned original L protocol bytes.

Retention is outside the mutable child journal. Each immutable stage dossier `stage_XX.json` holds `{schema:'root-L-retained-stage-v1',known,files,observed,request,retained_at,boot_id,root_post,root_post_transport}`. `known` is the exact required root-L-known-parent-return-v1 object; `files` is the complete readonly child-stage basename->spec inventory; observed preserves actual bounded manager bytes as canonical hex plus full transport custody; request is exact original actual dispatch. root_post and root_post_transport preserve a second actual ROOT systemctl cleanup readback. Custody.snapshot returns only known_raw/known_pin/files/inventory. Complete-return retention rechecks frozen stream semantics, returned object, claim/receipt leases, post-stop state and full inventory; failure returns are retained but cannot authorize advancement. Unknown/unfinalized files poison the directory. All retention writes use exclusive atomic link, fsync and exact readback; no replacement/retry.

Explicit formatting boundary: all new configs/wrappers/closure controls, original14 metadata, original journals and7 ROOT audit dossiers stay canonical. Original externally retained ROOT observation bodies reached through closure.evidence, eligibility.raw_credit_readback and quota.resource_readback need not be canonical: their exact original raw pins are checked first, then duplicate/nonfinite-rejecting JSON is parsed without re-encoding or changing their historical hash. Credit raw schema is root-live-eligible-credit-refresh-v1. No raw observation is normalized to make it pass.

Original14 stage request is bootstrap.json.request, also exactly claim.json, never a nonexistent dispatch.json. Original bootstrap schema marked-stage-launch-v1 binds config/expected_deployment_config_pin/request; original metadata controller_source_pin binds parent.files.controller.py, while gate.source_pins.parent binds the complete parent.manifest. Audit7 uses dispatch.json and its distinct full manager stream custody. Every basename inventory is reconstructed, not a selected metric projection.

Within one positively anchored Primitives instance, the full frozen10112-file runtime and21 historical closures are initially read/hash/semantically checked once. Later calls require the identical held evidence/config plus complete inventory and inode/device/size/mode/owner/nlink/mtime/ctime seals; any mutation rejects instead of reusing or re-fitting. Frozen V6 import guards remain active for scientific work. Caching never changes the original source clock or300/900/7200+200 limits.
